# 免费大模型 API 渠道导航

一份**免费大模型 API 渠道的结构化清单**，外加一个把它渲染成单文件页面的构建脚本。

`免费模型导航.html` 是数据内嵌的单文件产物，**双击即开，不需要起服务器、不需要联网、不需要装任何东西**。
里面 11 家渠道、130 多个免费模型，每条都标了「这条依据的是官方哪句话」。

> 本仓库是公开版。所有数据只采信**官方接口实测**与**官方页面原文**，
> 官方没说清的一律留空（`null`）并登记进「未证实清单」——**留白比编造有价值**。

## 我要怎么用

1. 下载 [`免费模型导航.html`](免费模型导航.html)，双击打开。
2. 「找模型」页按规格筛：输入/输出上限、模态、编程与中文评分、使用场景。
3. 「跨渠道对照」页看同一个模型在两家的规格差多少 —— **换渠道不换模型**是最省事的逃生路线。
4. 「渠道对比」页看各家的门槛、限额、坑点，以及成本估算（要切几段、日额度够跑几趟）。
5. 「接入配置」页导出 New API 的渠道配置（`priority` 已按降级链排好，`auto_ban` 已关）。
6. 想知道数据新不新：看页面顶部的**数据年龄提醒**和「政策变化」时间轴。

## 这个清单和别家聚合站的区别

| | 这里 | 一般聚合站 |
|---|---|---|
| 来源 | 只认官方接口 + 官方页面原文，每条带 `source_level` 与 `source_url` | 互相抄 |
| 拿不准的 | `null` + 进「未证实清单」，页面上显示「未核实」 | 填个看起来合理的数 |
| 政策变了 | `tools/check_live.py` 拉官方清单做机器对比，报「消失 / 新增免费 / 规格变动」 | 靠人发现 |
| 免费结束了 | 渠道从正式清单移进 `data/inbox.json` 草稿池，**每轮巡检继续点名** | 悄悄删掉 |
| 评分 | 主观（`【判】`），但**同一模型跨渠道强制统一**，冲突时看证据链 | 没有或各说各话 |

四条来源等级：`实` 实时接口实测 / `官` 官方页面原文 / `算` 按官方数字换算 / `判` 主观判断。
**只有前两档能作为收录依据。**

## 目录

```
免费模型导航.html     构建产物（数据内嵌，双击即开）
tools/
  build.py            构建 + 数据自检 + 到期提醒
  check_live.py       实况巡检：免 Key 拉各家官方模型清单，跟本地记录做机器对比
  probe.py            可用性探针（本地跑，Key 只存本地且已 gitignore）
  template.html       页面模板（改样式/交互改这里）
  git-hooks/pre-commit  提交前闸门（见「贡献」）
data/
  channels.json       渠道清单（家数以 build 输出为准）
  models/<渠道id>.json  每个渠道一个文件，文件名即渠道 id
  vendors.json        厂商档案
  meta.json           字段字典 + 枚举定义
  changes.json        政策变化时间轴（带日期）
  unverified.json     官方没说清楚的条目
  promos.json         优惠情报：官方在送折扣/限时免费、但按口径不进正式收录的纯文本
  inbox.json          草稿池：未核实的新渠道 + 已停止免费、仍在观察的渠道
```

## 数据模型（想改数据先看这节）

模型条目**必填只有 `id`**，其余可以留空，页面会显示「未核实」而不是假装有值。

| 字段 | 说明 |
|---|---|
| `vendor` | 厂商 key，对应 `vendors.json` 的 `id` |
| `ctx_in` / `ctx_out` | 输入 / 输出上限。**同名模型在不同网关可能差 4~7 倍**，按实际走的那个网关取值 |
| `modal_in` / `modal_out` | 数组：`text` / `image` / `audio` / `video` / `embedding` |
| `reasoning` | `none` / `toggle` / `effort` / `always`（官方档位枚举写进 `pitfall`） |
| `tools` / `structured` | `true` / `false` / 省略 = 未核实 |
| `usage` | 场景：`coding` / `writing` / `image` / `video` / `other`。`longctx`（输入 ≥500K）与 `multimodal`（有非文本输入）是**脚本派生**的，别手填 |
| `score_coding` / `score_zh` | 1–5 主观评分，省略 = 未评估 |
| `specialty` / `pitfall` | 一句话专长 / 坑点 |
| `free_type` | `permanent` / `beta` / `promo` / `client` / `variant` / `quota` |
| `expiry` | 失效日期，无则省略 |
| `available_cn` | 三态：`true` 实测可用 / `false` 官方明示该地区不可用 / 省略 = 继承渠道级值 |
| `source_level` | `实` / `官` / `算` / `判` |
| `verified_at` | 核实日期 |

**调度字段**（撞墙之后全靠它们）：`limit_scope`（限额是渠道级共享还是按模型/Key —— 决定换模型有没有用）、
`quota_reset`（`daily` / `rolling-5h` / …，决定该硬刚还是等重置）、`daily_cap`、`newapi`。

叙述字段里**只认反引号**（`` `x` `` 渲染成 `<code>`），其他 Markdown 不解析；换行写 `\n`。

## ⚠️ `verified_at` 新鲜 ≠ 数据没变

这是本项目最重要的一条认知，也是 `check_live.py` 存在的理由。

拿 `verified_at` 减今天，回答的是**「你多久没看了」**，不是**「政策动没动」**。
免费政策可以在一两天内悄悄改掉，不预告、不发公告；新模型上架同样没有提前通知。

现成例子：某次数据两天前刚核实过，按日期算「全部在保质期内」；
同一时刻 `check_live.py` 拉官方接口对比，发现 **14 个模型已从官方清单消失**，外加 2 个新免费模型悄悄上线。

**真正的基线是「上次看到的官方实况」，不是「上次核实的日期」。**

## 更新流程（两步，中间那一步故意留给人）

```bash
python tools/check_live.py    # 1. 出差异清单（只读官方接口，不改任何数据文件）
#  2. 人看差异清单，圈定处理哪几条 —— 这一步是本项目唯一的把关点
python tools/build.py         # 3. 重建产物 + 数据自检 + 到期提醒
```

命令都在**仓库根目录**下跑。`check_live.py` 的边界：不读任何 Key，所以带 Key 才能查的那几家
会落在报告的 `skipped` 里，必须靠人联网核官方文档，**不能因为报告说「0 处变化」就当查过了**。

> 曾经有过一个「一键更新」脚本，已删除。因为它把「巡检 → 看差异 → 人工决定 → 再构建」压成一步，
> 恰好跳掉了中间那步。也不要提议加回来。

## 收录口径（提 PR 前先对一遍）

一条免费路线要进 `channels.json` / `data/models/`，得同时过两问 —— **命中任一就不是**：

1. **要不要先掏钱才算数**？付费订阅内的免费档、错峰折扣、首月翻倍都不算白嫖路线。
2. **是不是只发给新注册账号的一次性限量体验**？「注册送 N 天 / N 积分」「首用 5 天内每天 N token」都不算。

两问都不命中的才进正式清单。命中第 1 问但确属官方优惠的，进 `data/promos.json` 记一条纯文本
（页面「优惠情报」页签），**不参与任何计数与筛选** —— 某家出现在那页，意味着它没被收录。

判不准的先进 `promos.json`，作为一个判断题提出来，别塞进正式数据。

## 贡献

- 改任何数据后跑 `python tools/build.py`，**看自检有没有新告警**。当前基线是 **0 告警**，
  所以再冒出任何告警都当新问题查。
- 建议挂上提交前闸门（它会跑数据自检 + Key 泄漏硬红线，有告警直接中止提交）：
  ```bash
  git config core.hooksPath tools/git-hooks
  ```
- **撤一条模型 / 改一个规格数值，要同步改完六处派生文字**，只删条目会留下自相矛盾的记录：
  该渠道 `channels.json` 的 `free_model_count` 与 `notes`、`vendors.json` 里该厂商的
  `free_note` / `verdict`、`data/changes.json` 追加一条（带日期 + 官方字段依据）、
  **别家渠道条目里指向它的交叉引用**、**厂商 `verdict` 里引用过的数值**。
  ⚠️ 构建自检**查不出后两类**，落库前必须自己拿「被撤的模型 ID」和「被改掉的那个数值」
  当关键词 grep 一遍 `data/*.json` + `data/models/*.json` 的叙述字段。
- 判「消失」前在同一家再拉一次确认（免费端点会偶发 5xx，单次拉不到不等于下架）。
- 新增渠道三步：`channels.json` 加一条 → `data/models/<id>.json` 建数组文件 →
  **在 `tools/check_live.py` 的 `LIVE` 或 `SKIP` 登记这个 id**。漏第三步，巡检会把它列成「未登记」盲区并当场点名。
- 官方没说清的，往 `data/unverified.json` 加一条，别在数据字段里编。

## 免责

- 数据是**某个时点对官方页面的核实结果**，随时会过期。用之前看 `verified_at` 和「政策变化」时间轴，
  真要确认就自己跑一次 `check_live.py`。
- 各家免费政策、地区可用性、限速都由厂商自己定，**以官方页面为准**。本清单不构成任何绕过
  地区限制或使用条款限制的建议。
- 本仓库不含任何 API Key。`data/.keys.local.json` 已在 `.gitignore` 里，
  `build.py` 有硬红线：产物里匹配到 `nvapi-` / `sk-` / `sk-ant-` 形状会直接中止构建。
